OWASP Top 10 (2025) — A03: Software Supply Chain Failures
Complete Notes for Theory + Interview + Practical Understanding
________________________________________
1. What is Software Supply Chain?
Before understanding the vulnerability, understand the term:
Software Supply Chain
Think of software like a car.
A car company does NOT manufacture:
•	every bolt 
•	every wire 
•	every chip 
Instead, it buys parts from suppliers.
________________________________________
Software Works the Same Way
Developers use:
•	libraries 
•	frameworks 
•	plugins 
•	packages 
•	containers 
•	APIs 
•	CI/CD tools 
built by others.
________________________________________
Example
Your application:
My Website
uses:
React
Node.js
Express
Bootstrap
jQuery
JWT Library
Docker Image
GitHub Actions
Many external components.
This entire ecosystem is called:
Software Supply Chain
________________________________________
2. What is Software Supply Chain Failure?
It occurs when:
A dependency, package, tool, build system, or third-party component introduces security risk.
The application itself may be secure.
But one component in the chain is compromised.
________________________________________
Simple Definition
Trusting software components without proper verification and security controls.
________________________________________

6. Main Types of Supply Chain Failures
For interviews and pentesting remember these 6.
________________________________________
Type 1 — Vulnerable Dependencies
MOST COMMON.
Application uses:
Outdated library with known vulnerability.
________________________________________
Example
Application uses:
Log4j
Old vulnerable version.
Attacker exploits it.
Application gets compromised.
________________________________________
Flow
Developer installs package
        ↓
Package contains vulnerability
        ↓
Application deployed
        ↓
Attacker exploits dependency
________________________________________
Type 2 — Malicious Packages
VERY IMPORTANT.
Attacker uploads:
Fake package
to package repository.
Developer installs it.
________________________________________
Example
Developer intended:
requests
but installs:
requestss
(fake lookalike package)
This is called:
Typosquatting
________________________________________
Type 3 — Dependency Confusion
VERY IMPORTANT INTERVIEW TOPIC.
________________________________________
What Happens?
Company has internal package:
company-auth
Attacker uploads package with same name publicly.
Build system downloads attacker's package.
________________________________________
Flow
Internal package exists
         ↓
Attacker creates same package publicly
         ↓
Build process downloads attacker's package
         ↓
Malicious code executed
________________________________________
Type 4 — Compromised Build Pipeline
VERY IMPORTANT.
Attacker compromises:
•	Jenkins 
•	GitHub Actions 
•	CI/CD server 
Then injects malicious code into builds.
________________________________________
Flow
Source Code
      ↓
CI/CD Pipeline
      ↓
Attacker modifies build
      ↓
Malicious application released
________________________________________
Type 5 — Compromised Updates
Software update mechanism compromised.
________________________________________
Example
Trusted application update server hacked.
Users download:
Malicious update
thinking it is legitimate.
________________________________________
Type 6 — Vulnerable Container Images
VERY COMMON TODAY.
Developers pull:
latest
container image.
Image contains:
•	outdated packages 
•	known CVEs 
•	malware 
________________________________________

15. Prevention
MOST IMPORTANT.
________________________________________
1. Dependency Scanning
Scan packages for known CVEs.
Tools:
•	Dependabot 
•	Snyk 
•	Trivy 
________________________________________
2. Use Trusted Repositories
Install packages only from trusted sources.
________________________________________
3. Verify Packages
Check:
•	signatures 
•	maintainers 
•	source 
________________________________________
4. Maintain SBOM
Know every dependency.
________________________________________
5. Secure CI/CD
Protect:
•	secrets 
•	pipelines 
•	build servers 
________________________________________
6. Update Regularly
Patch vulnerable libraries.
________________________________________
7. Principle of Least Privilege
Dependencies should not have unnecessary permissions.

16. Interview Questions
________________________________________
Q1. What is Software Supply Chain?
The ecosystem of third-party libraries, dependencies, build tools, repositories, and services used to develop and deliver software.
________________________________________
Q2. What is Software Supply Chain Failure?
Security weaknesses introduced through dependencies, packages, CI/CD systems, or third-party components.
________________________________________
Q3. What is Dependency Confusion?
An attacker publishes a package with the same name as an internal package, causing systems to install the malicious version.
________________________________________
Q4. What is Typosquatting?
Creating malicious packages with names similar to popular packages to trick developers.
________________________________________
Q5. What is SBOM?
Software Bill of Materials — a list of all software components and dependencies used in an application.
________________________________________
Q6. Give a famous example.
Log4Shell (Log4j vulnerability)
