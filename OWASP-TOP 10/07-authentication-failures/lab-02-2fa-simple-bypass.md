## Objective

Identify a flaw in the two-factor authentication (2FA) workflow that allows access to a user's account without completing the verification step.

---

## Vulnerability Overview

Two-Factor Authentication (2FA) adds an extra layer of security by requiring users to verify their identity after entering valid credentials.

In this lab, the application verifies the username and password but fails to properly enforce the second authentication step. By directly requesting a protected page, it is possible to bypass the verification process and gain access to the account.

---

## Lab Scenario

The application requires users to enter a verification code after logging in.

After authenticating as another user, instead of submitting the verification code, the protected account page can be accessed directly by modifying the URL. Since the server does not verify whether the second authentication step has been completed, access is granted without 2FA verification.

## Result

The application failed to enforce the second factor of authentication before granting access to protected resources.

By directly requesting the account page, the 2FA verification process was bypassed, allowing unauthorized access.

# Impact

Successful exploitation could allow an attacker to:

- Bypass two-factor authentication
- Access protected user accounts
- Compromise sensitive user information
- Perform unauthorized actions as another user
- Reduce the effectiveness of multi-factor authentication

---

# Root Cause

The application validated the username and password but failed to verify whether the second authentication step had been completed before allowing access to protected resources.

Authorization decisions relied only on the authenticated session and did not confirm successful 2FA verification.

---

# Remediation

- Enforce successful 2FA verification before granting access to protected pages.
- Track the authentication state on the server instead of relying on client-side navigation.
- Redirect users who have not completed 2FA back to the verification page.
- Validate the user's authentication stage for every protected request.
- Perform regular security testing of authentication workflows.

---

# Key Learning

This lab demonstrates that implementing 2FA alone is not enough. The application must ensure that every protected resource verifies the user's authentication state before granting access.

A weak authentication workflow can completely undermine the security benefits of multi-factor authentication.
